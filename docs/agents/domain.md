# Domain docs

Single-context layout: `GLOSSARY.md` at the repository root and
numbered ADRs under `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If absent, proceed silently. Domain-modeling creates these documents
lazily when terms or decisions are resolved.

Use the glossary's vocabulary in issues, proposals, hypotheses, and
tests. Reconsider invented terminology; note genuine gaps for
domain-modeling.

Explicitly surface conflicts with existing ADRs, citing the ADR
and explaining why the decision merits reopening.
